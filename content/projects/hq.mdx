## Context

I run a small web practice and I'm a full-time student. The limit on both is my own
attention, so I built a team of agents to take the planning, building, reviewing and
reporting, and kept the decisions that carry risk for myself.

The code is private because it holds my schedule and business records. This page is
the part I can show, and every number on it comes from a script you can read.

## What it is

An agent organization with a clear chain of command. A coordinator (the Boss) takes
my instructions and hands out work. Four managers own an area each: agency work,
products, research, and career and school. A secretary writes my daily plan, a
ChatGPT advisor gives a second opinion, and builder agents on Claude and Codex write
the code.

The rule that makes it safe to leave running: agents plan, build, review and report,
and I decide. Spending money, sending anything to a real person, creating accounts
and merging to main are mine. An agent that needs one of those puts a card in my
inbox with its recommendation, and carries on with other work.

## How it's built

- **A Node command line and a SQLite task store.** Every work order lives in the
  store with an owner, a goal, a definition of done and a full history. An agent
  claims a work order for a 60-minute lease and reports it done, failed, blocked or
  waiting for my approval. A claim that runs out its lease goes back to the
  coordinator instead of sitting forever.
- **Approvals tied to one exact action.** An approval is bound to the specific
  action it was given for, so a message or a document can't stretch it to cover
  something else.
- **A dashboard and an inbox.** What needs me shows up first on a phone-sized page,
  with the agent's recommendation next to each question.
- **Claude and Codex lanes.** Claude sessions run the managers and the secretary.
  Codex handles mechanical code in its own sandbox. Cheaper tools go first: a
  script before a small model before a large one.
- **GitHub trains with reviews.** Agents push branches and open pull requests. They
  can't merge. A continuous-integration job runs the test suite on each pull request
  and an independent review runs before it reaches me.
- **A scheduler in plain code.** It writes my plan each morning and only pushes my
  phone when something needs me.

not hidden: I'd rather show a suite that is mostly green than one that
reads as perfect.

## What I'm not claiming

No revenue, no hours saved and no client results. I haven't measured any of them
for HQ, and a figure with no recorded before and after is the kind of thing this
site is meant to refuse. The numbers above are activity, not outcomes: they show
that the system runs and that its work passes through review, not that it earns.
