## Context

My deadlines live in three places. Canvas has most of them, Gradescope has the ones
a course posts only there, and Ed has announcements that move dates. Canvas also
makes it slow to get your own course files out. I wanted one page that answers
"what is due in the next two weeks" and one button that saves a course's materials
to a folder I choose.

I did not want a tool that holds my login or sends my coursework to a server. So the
rule from the start was that the data never leaves the browser unless I turn
something on.

## What it is

A Chrome extension. It reads Canvas, Gradescope and Ed with the sign-in your browser
already has, so it never asks for a password or a Canvas access token. There is no
backend and no analytics.

- **Upcoming.** Everything due in the next 14 days across all courses, merged from
  the three sites and de-duplicated.
- **Files.** Saves a course's modules, files, pages, assignments, announcements and
  syllabus into a folder you pick. It only fetches what changed since the last run.
- **Week schedule.** A weekly page built from your class times and the deadlines.
- **Course chat.** Ask a question about a course and get an answer with the passages
  it came from. It is off for every course until you tick that course's box, and it
  uses your own API key.
- **Opt-in extras.** A due date file synced to a GitHub repo you name, and a nightly
  file run. Both are off by default.

It is read-only toward every site it touches. It never submits, edits or deletes
anything on Canvas, Gradescope or Ed.

## How it's built

- **WXT and Manifest V3.** TypeScript throughout, React for the pages. The
  background worker does the fetching, and six pages sit on top of it: popup,
  Upcoming, Files, Chat, Schedule and Settings.
- **Small permissions.** Three browser permissions and four site addresses, listed
  below. No access to your tabs, cookies or every website.
- **Consent before reading.** A first run screen explains what is read and what is
  not. Until you accept it, no page and no background job fetches anything. Settings
  has a withdraw button that stops all reading.
- **A frozen Python version came first.** I wrote a command line tool before the
  extension. It stopped at a working login and course list, and I kept it because
  its tests record how Canvas really behaves, such as signalling throttling with a
  403 instead of a 429 and paging results through a `Link` header.
- **One slice per pull request.** Each feature is its own pull request, stacked on the
  one before, with unit tests on the pure logic and a note on what was not checked
  against a live account.

## Where it stands

Built and tested. Not published. I have not put it on the Chrome Web Store, and it
has no users, so there are no adoption numbers on this page and I'm not implying
any.

It is also Cornell only. The only Canvas address in the manifest is Cornell's, and
adding another school is a one line change plus a new store listing. I chose not to
widen it, because asking for every Canvas host or every site would make a browser
review harder and ask for more access than the tool needs.

Two things are still unverified. I have not run the packaged build against a real
account from start to finish, and the Gradescope reader is a plain text parser that
has not been checked against a live page.

## What I'm not claiming

No users, no downloads, no reviews and no time saved. The numbers above are the size
and test state of the code, not results from people using it. I also have not decided
whether to publish. Course materials belong to the student and the school, and
Cornell's rules on third party tools and AI services are worth reading before a
public listing, so that call is still open.

## What's next

Decide whether it goes on the store at all. If it does, the open steps are a hosted
privacy policy page, a contact address on it, the developer account, and one run of
the exact packaged build on a real Cornell account first.
